01 · Project Overview

What is NeuroVerse?

Think of every major AI tool — ChatGPT, Cursor, Perplexity, Zapier, Notion AI — fused into one autonomous operating system that acts on your behalf without manual intervention.

🎯 The Core Idea
User speaks a goal. The system autonomously: searches the web, reads PDFs, explores GitHub, creates study roadmaps, generates quizzes, schedules tasks, tracks progress, and produces notes — all without a single manual step.
🧠 What Makes It Research-Level
Multi-layer agent memory (short-term, long-term, episodic, semantic) combined with a self-improving agent loop that evaluates, diagnoses, fixes, and retries — making it a publishable system, not just a demo.
⚡ Real-World Use Case (Demo)
User says "Prepare me for my Data Science interview." System launches 5 agents in parallel: research agent finds topics, planner builds a 7-day schedule, coding agent finds practice repos, memory agent recalls what you already know, monitor agent tracks your quiz scores.
🏗️ Why This Architecture?
Spring Boot as an enterprise gateway brings robustness that most AI projects skip. Kafka enables true async agent communication. LangGraph gives stateful multi-step reasoning. Together they create a system that handles real production-scale complexity.

SPRING BOOT — WHY IT'S THE MAIN BACKEND
  • Handles all HTTP/WebSocket connections from frontend
  • JWT authentication — every API call is verified here
  • Rate limiting — prevents API abuse
  • Kafka producer — pushes tasks as events to agents
  • Kafka consumer — receives agent results and pushes to UI via WebSocket
  • User management, task history in PostgreSQL via JPA
  • Swagger UI auto-generated for all endpoints
  • Deployed independently on Render as a Docker container
KAFKA — WHY NOT DIRECT HTTP CALLS
  • Agents are async — they don't block each other
  • Spring Boot doesn't wait for AI to finish — it just publishes an event
  • Agents can fail and retry without losing the message
  • Multiple agents can consume the same task independently
  • Perfect audit trail — every agent action is an event

05 · End-to-End Workflow

What Happens Step by Step

Tracing one user request — "Prepare me for my Data Science interview" — through every layer of the system from click to output.

STEP 01User Input
User types or speaks: "Prepare me for my Data Science interview". Next.js frontend sends a REST POST to Spring Boot gateway with JWT token attached.
STEP 02Gateway Processing
Spring Boot verifies JWT, rate-checks the user, creates a Task record in PostgreSQL (status: PENDING), and publishes event to Kafka topic task.new. Returns task ID to frontend immediately — no waiting for AI.
STEP 03Kafka Event
Kafka delivers the event to FastAPI Python consumer. Frontend opens a WebSocket subscription to receive real-time updates on this task ID.
STEP 04LangGraph Orchestration
LangGraph decomposes the task into sub-tasks and launches all 5 agents. Memory Agent checks prior history first. Agents run in parallel where possible. Each agent result is an intermediate state update.
STEP 05Agent Execution
Research Agent hits Tavily API + PDF store. Planner Agent calls Calendar MCP. Coding Agent queries GitHub MCP. All agents call Groq API (Llama 3.1 70B) for reasoning. Monitor Agent scores each output against quality rubric.
STEP 06Result Streaming
Each agent publishes results to Kafka topic task.result. Spring Boot consumes and pushes to frontend via WebSocket STOMP. User sees sections appear live as agents finish.
STEP 07Final Output
User receives: 7-day study roadmap + 20 practice questions + GitHub repos + calendar events already created + topic notes saved to Drive. Memory Agent stores this session for future reference.

task.new         → Spring Boot → FastAPI
task.result     → FastAPI → Spring Boot
agent.log       → All agents → MLflow

RAG PIPELINE DETAIL
1. Ingest
PDF/web content → chunked → embedded via HuggingFace sentence-transformers
2. Store
Vectors → ChromaDB. Metadata → PostgreSQL. Keywords → BM25 index
3. Retrieve
Hybrid: dense (cosine similarity) + sparse (BM25) → RRF fusion re-ranking
4. Generate
Top-k chunks → Groq (Llama 3.1 70B) → structured answer with citations

07 · Agent Memory System

4-Layer Memory Architecture

What makes this research-grade: a multi-layer memory system that lets agents remember what you learned last week, how you performed on quizzes, and what you already know — without being told again.

Short-Term
Redis · Upstash
Current conversation context, last 10 messages, active task state. Expires after session ends (sliding window).
Long-Term
PostgreSQL + ChromaDB
User preferences, topic mastery scores, study history across sessions. Persists indefinitely. Queried before each task.
Episodic
PostgreSQL Events Table
Logs of what the agent did, what worked, what failed. Enables the self-improving loop. Feeds MLflow experiments.
Semantic
ChromaDB Collections
Knowledge embeddings: concepts the user has learned, topic relationships, source documents. Used in every RAG query.
# Memory Agent — query flow before every agent action async def retrieve_context(user_id: str, query: str): # 1. Short-term: get recent context from Redis recent = await redis.get(f"session:{user_id}:context") # 2. Semantic: vector search ChromaDB for relevant knowledge semantic = chromadb.query(query_embeddings=[embed(query)], n_results=5) # 3. Episodic: fetch past experiences for this task type episodes = db.query("SELECT * FROM episodes WHERE task_type=? ORDER BY timestamp DESC LIMIT 3") # 4. Long-term: user mastery profile profile = db.query("SELECT * FROM user_mastery WHERE user_id=?", user_id) return merge_context(recent, semantic, episodes, profile)

Advanced Memory, Self-Improvement, Monitoring & Deployment
Build the multi-layer memory system, implement the self-improving agent loop, add MLflow experiment tracking, wire Prometheus + Grafana, Docker everything, and deploy the full production system. Write the research paper.
WEEK 05 4-Layer Memory System (Research-Grade) Memory Architecture
1
Design PostgreSQL schema for long-term memory: user_mastery(user_id, topic, score, last_reviewed), episodes(agent, task_type, input, output, quality_score, timestamp).
2
Implement short-term memory: Redis sliding window (last 10 exchanges per user). Auto-expire after 2 hours of inactivity.
3
Implement long-term memory: after each session, Memory Agent extracts key learnings and updates user_mastery table with spaced-repetition scoring (SM-2 algorithm).
4
Implement episodic memory: every agent action → write to episodes table via Kafka agent.log topic. Monitor Agent reads this to learn what works.
5
Implement semantic memory: build dedicated ChromaDB collection per user. Embed all learned concepts. Memory Agent queries this before Research Agent runs — prevents redundant searches.
6
Build memory retrieval fusion: Memory Agent merges all 4 layers into a unified context object before passing to LangGraph. Test: run same query twice → second run should use cached knowledge.
WEEK 06 Self-Improving Agent + Quiz Generator + Progress Tracker Self-Improvement
1
Build self-eval loop in Monitor Agent: after each task output, call Groq with evaluation prompt. Score: relevance (0–10), completeness (0–10), accuracy (0–10). If avg < 7, flag for retry.
2
Build retry mechanism: Monitor Agent publishes to Kafka agent.retry with failure diagnosis. LangGraph re-routes to the failed agent with an improved prompt based on the diagnosis.
3
Add MLflow experiment tracking: log every agent run as an MLflow experiment (params: model, prompt version, temperature; metrics: quality score, latency, tokens used).
4
Build quiz generator: after Research Agent finds topics, Planner Agent calls Groq with a structured prompt to generate 10 MCQs. Store in PostgreSQL. Serve via Spring Boot API.
5
Build progress tracker: when user answers quizzes, score is stored in user_mastery. Frontend dashboard shows topic-by-topic mastery bars.
6
Add real-time WebSocket streaming: agents push partial results as they arrive. UI shows animated "agent thinking" indicators per agent type. User sees progress, not just final output.

Add Prometheus metrics to FastAPI (prometheus-fastapi-instrumentator). Track: agent execution time, Groq API latency, retry count, memory hit rate.
